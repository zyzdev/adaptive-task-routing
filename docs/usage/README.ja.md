# Adaptive Task Routing — ユーザーガイド

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**必要な作業に AI の利用枠を使い、見落としや手戻りを減らすために。**

Adaptive Task Routing は、次の重要な作業段階に入る前に、新しい会話を始めるべきか、どのモデルと推論強度が適しているかを提案し、利用量と作業の信頼性のバランスを取る手助けをします。

- **以前のタスクによる干渉を減らす：** 新しい会話を始めるタイミングを判断し、AI が以前の前提や制約を新しい作業に持ち込む可能性を下げます。繰り返しの訂正や手戻りを減らし、引き継ぐべき情報は必要に応じて要約します。
- **不要な利用量を抑える：** 「最低限十分」と「推奨」のモデル・推論設定を示し、引き上げる価値があるかを説明します。すべてのタスクで最高設定を使う必要はありません。
- **見落としや手戻りのリスクを下げる：** 複雑な作業の開始前に必要なモデル能力と推論強度を評価し、能力不足の設定による失敗を減らす手助けをします。
- **最終判断はユーザーに：** 提案を見てから決めることも、プラットフォームが対応していれば自動適用を選ぶこともできます。

話題が変わっただけで新しい会話が必要になるわけではありません。不要な履歴の影響を減らしつつ、次のタスクに必要な情報を残すことが目的です。実際の節約や信頼性の改善は、タスクと採用した設定に左右されます。

## 仕組み

1. AI が実行可能な計画を提示するか、依頼された分析や確認結果をまとめます。
2. 次の段階について、まず会話を続けるか新しく始めるかを提案し、続いて最低限十分な設定、推奨設定、設定を引き上げる価値を示します。
3. 既定の `ask` はユーザーの判断を待ちます。`auto` は対応していて結果を検証できる変更を適用します。切り替えられない場合はその旨を伝え、現在の設定で承認済みの作業を続けます。

短い質問や小さな操作ではルーティングを省略し、不要な判断や待ち時間を増やしません。

## インストール

### Gemini CLI

```bash
gemini extensions install https://github.com/zyzdev/adaptive-task-routing-gemini --ref v0.4.2
```

インストール後、Gemini CLI を再起動してください。

### Claude Code

公開ディレクトリへの申請は審査中です。掲載されるまでは、専用リポジトリをクローンし、プラグインディレクトリを指定して Claude Code を起動できます。

```bash
git clone --branch v0.4.2 https://github.com/zyzdev/adaptive-task-routing-claude.git
claude --plugin-dir "$PWD/adaptive-task-routing-claude"
```

### ChatGPT と Codex

[v0.4.2 Release](https://github.com/zyzdev/adaptive-task-routing/releases/tag/v0.4.2) から `adaptive-task-routing-openai-0.4.2.zip` をダウンロードしてください。ローカルプラグインに対応した画面では、展開したプラグインを Plugin または Marketplace の機能から追加します。公開ディレクトリでの提供は OpenAI の審査結果によります。

## 最初の使い方

インストール後に新しい会話を開始し、ある程度大きなタスクを入力します。例：

> このプロジェクトのリリース手順、プラットフォーム間の整合性、テストの不足を調査してください。

AI は先に有用な調査結果または実行可能な計画を提示します。次の段階がルーティング対象の場合、続けて **Adaptive Task Routing** のリソース提案が表示されます。

- 現在の会話を継続するか
- 最低限十分なモデルと推論強度
- 推奨モデルと推論強度
- 必要な場合はアップグレードの価値

既定の `ask` モードでは、提案後に一時停止して自然な返答を待ちます。設定を変更する、そのまま続ける、別の方法を指定する、のいずれも選べます。決められた返信文は不要です。

## 表示される内容

以下は「プラグインのリリース工程、プラットフォーム間の整合性、テスト不足を確認する」という依頼の例です。実際の計画と提案は、タスクやプラットフォームに応じて変わります。

### 応答例

#### 1. AI のタスク計画

```text
1. リリーススクリプトと各プラットフォームの Manifest を確認する。
2. CI、バージョン、テストの不足を確認する。
3. リスクと修正順序をまとめる。
```

#### 2. Adaptive Task Routing のリソース提案

```text
---

### Adaptive Task Routing｜タスクリソースの提案

以下は、上記計画の次の段階に適した会話環境、モデル、推論設定の提案です。

【会話設定】
* 提案：現在の会話を続ける
* ウィンドウを切り替える：いいえ
次の段階に必要な要件と証拠が現在の会話に残っているため、そのまま続けます。

【最低限十分な AI 設定】
* Model：GPT-5.6 Sol
* Reasoning：high
複数ファイルの確認と通常の検証には十分です。

【推奨 AI 設定】
* Model：GPT-6 Astra
* Reasoning：high
* アップグレード価値：中。プラットフォーム間の設定にある見落としやすい関連を追跡しやすくなります。

現在の環境ではモデルと推論強度を自動変更できません。必要に応じて画面の選択肢から変更してください。設定を変更するか、現在の設定で次の段階へ進むかを決めるまで、ここで待機します。
```

`ask` モードはここで停止します。`auto` モードはホストが対応し、結果を検証できる変更だけを適用し、承認済みの作業を続けます。Gemini ではネイティブのモデル別名を使用し、通常 Reasoning は「モデル既定値」と表示されます。

## 明示的に起動する

- Skill メンション対応の Codex：`$adaptive-task-routing`
- Claude Code：`/adaptive-task-routing:adaptive-task-routing`
- その他：「この作業を始める前に adaptive-task-routing Skill を使用してください」と依頼します。

## モード

- `ask`（既定）：提案を表示し、大規模な実行の前にユーザーの返答を待ちます。
- `auto`：現在のホストが許可し、結果を検証できる変更だけを適用して続行します。
- `off`：該当 Router を実行しません。

会話ルーティングとモデルルーティングは別々に設定でき、AI との会話から直接変更できます。例：

- 「この会話では Adaptive Task Routing を auto にしてください」
- 「モデルルーティングを ask にしてください」
- 「今回だけ会話ルーティングを off にしてください」
- 「現在の二つのルーティングモードを教えてください」

Router を指定しない Adaptive Task Routing のモード変更は両方に適用されます。AI はルーティング提案を実行せず、実際の値と適用範囲をすぐに確認します。新しい会話にも引き継ぐには、既定値として保存するよう明示してください。ホストに書き込み可能なユーザー設定がない場合は現在の会話だけに適用され、その制限が表示されます。

## アンインストール

Gemini CLI：

```bash
gemini extensions uninstall adaptive-task-routing
```

Claude Code を `--plugin-dir` で起動した場合は、そのセッションを終了してクローンしたディレクトリを削除します。ChatGPT または Codex では、インストールに使用した Plugin または Marketplace の画面から無効化または削除してください。

## トラブルシューティング

- インストールまたは更新後は、新しい会話を開始してください。
- Skill 一覧に `adaptive-task-routing`、`task-context-router`、`research-model-router` があることを確認してください。
- 提案が表示されない場合は、一度明示的に Skill を起動してください。
- 提案の表示だけでは、モデルや会話が切り替わったことを意味しません。検証できた自動変更だけが適用済みとして報告されます。

開発と検証の詳細は[プロジェクト README](../../README.md)を参照してください。
