End-to-end publishing guide

三平台完整發布手冊

將 Adaptive Task Routing 從單一來源建置成三份經過驗證的發布產物，分別送到 OpenAI／ChatGPT／Codex、Claude Code 與 Gemini CLI。

目前正式版本v0.4.2
GitHub Release已發布
文件更新日期2026-09-12

1. 確認發布範圍

三份套件共享 skills/ 與 shared/ 來源，但安裝格式與公開管道不同。

OpenAIChatGPT／Codex Plugin Portal，上傳 OpenAI ZIP。
Claude Code公開 GitHub plugin repository，再申請 Plugin Directory。
Gemini CLI公開 GitHub extension repository，供 URL 安裝與 Gallery 探索。
介面限制：Claude 套件目標是 Claude Code；Gemini 套件目標是 Gemini CLI。它們不是一般 Claude 或 Gemini 聊天 App 的 Extension 安裝包。

2. 備妥公開資料

正式送審前，先準備真實且可公開查閱的資料。不要在 Manifest 或表單中填入暫時占位內容。

  • 發布者／組織名稱
  • 聯絡信箱
  • 產品首頁
  • 支援頁面
  • 隱私權政策
  • 服務條款
  • Logo 與截圖
  • 支援國家與語言
  • Starter prompts
  • 正向與負向測試證據

3. 建立版本分支

  1. 從最新 main 建立分支
    git switch main
git pull --ff-only origin main
git switch -c release/0.4.3
  2. 更新版本與 Changelog

    調整 release.json，將完成的項目從 Unreleased 移入新版本區塊，並同步 README、架構與驗證文件中的目前版本。

  3. 先以 PR 審查

    版本變更只在發布分支進行；測試與審查通過後才合併到 main。

4. 建置與驗證三平台產物

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt

.venv/bin/python scripts/validate_release.py --source-only
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/build_release.py
.venv/bin/python scripts/validate_release.py --require-archives

claude plugin validate dist/claude/adaptive-task-routing --strict
gemini extensions validate dist/gemini/adaptive-task-routing
.venv/bin/python scripts/smoke_local.py

(cd dist && shasum -a 256 -c SHA256SUMS)

所有指令都成功後，才提交版本來源：

git add CHANGELOG.md README.md README.zh-TW.md docs release.json
git commit -m "release: prepare 0.4.3"
git push -u origin release/0.4.3

gh pr create \
  --base main \
  --head release/0.4.3 \
  --title "Release adaptive-task-routing 0.4.3" \
  --body-file /path/to/release-notes.md
產物規則：dist/ 是可重建且不納入 Git 的輸出。ZIP 必須讓平台 Manifest 直接位於壓縮檔根層，不能再包一層資料夾。

5. 建立 GitHub Tag 與 Release

發布 PR 合併後，再從最新 main 建立 tag。版本 tag 必須是非空且格式有效的 vX.Y.Z。

git switch main
git pull --ff-only origin main

gh release create v0.4.3 \
  dist/adaptive-task-routing-openai-0.4.3.zip \
  dist/adaptive-task-routing-claude-0.4.3.zip \
  dist/adaptive-task-routing-gemini-0.4.3.zip \
  dist/SHA256SUMS \
  --target main \
  --title "Adaptive Task Routing 0.4.3" \
  --generate-notes

若使用 GitHub 網頁，於 Choose a tag 輸入完整版本，例如 v0.4.3，再選擇 Create new tag on publish，Target 指向 main。

6. 發布至 OpenAI／ChatGPT／Codex

  1. 確認帳戶條件

    完成發布者或組織身分驗證，並確認帳戶有 Apps Management Write 權限。

  2. 建立 Skills-only Plugin

    開啟 OpenAI Plugin Portal，選擇 Create plugin，再選 Skills only。

  3. 上傳正確檔案

    使用 dist/adaptive-task-routing-openai-版本.zip。不要上傳 monorepo，也不要使用 Claude 或 Gemini ZIP。

  4. 核對匯入結果

    確認三個 Skills 與需要的 shared/ 檔案都被匯入。

  5. 完成商店資料

    填寫 Logo、分類、開發者身分、網站、支援、隱私權、條款、Starter prompts、地區與聲明。

  6. 加入測試證據

    使用專案的五個正向與三個負向案例，填入實際操作結果。

  7. 先 Submit，再 Publish

    送出審核不等於公開上架；審核通過後還要另外執行 Publish。

官方參考：Plugin 建置、提交與發布。

7. 發布至 Claude Code

  1. 建立專用公開 repository

    建議使用 adaptive-task-routing-claude。將 dist/claude/adaptive-task-routing/ 的內容放在 repository 根目錄。

  2. 核對根目錄
    .claude-plugin/plugin.json
skills/
shared/
README.md
  3. 驗證遠端 checkout
    claude plugin validate /absolute/path/to/checkout --strict
claude --plugin-dir /absolute/path/to/checkout
  4. 重新執行行為測試

    在新的 Claude Code session 測試隱式觸發、明確 Skill 呼叫、ask 停留、對話視窗與模型建議。

  5. 送交公開目錄

    前往 Claude Plugin 提交表單，提供 repository、plugin 路徑、版本、發布者資料與測試證據。

  6. 驗證正式安裝來源

    通過審核後，從正式 marketplace 在新 session 安裝並再次測試。

官方參考：Claude Code Plugins。

8. 發布至 Gemini CLI

  1. 建立專用公開 repository

    建議使用 adaptive-task-routing-gemini。將 dist/gemini/adaptive-task-routing/ 的內容放在 repository 根目錄。

  2. 核對根目錄
    gemini-extension.json
GEMINI.md
skills/
shared/
README.md
  3. 新增 Gallery topic

    在 GitHub repository 的 About → Topics 加入 gemini-cli-extension。

  4. 建立版本 tag

    在 Gemini 專用 repository 建立與來源一致的 tag，例如 v0.4.2。

  5. 從正式 URL 安裝
    gemini extensions install \
  https://github.com/zyzdev/adaptive-task-routing-gemini \
  --ref v0.4.2

gemini extensions list
gemini skills list
  6. 等待 Gallery 探索

    topic 與格式符合要求後，Gallery 才可能收錄；本機 validation 通過不代表保證上架。

Gemini Release 附件：Gemini 專用 repository 的 Release 只附 Gemini ZIP 與 checksum，避免多個通用 ZIP 讓安裝器選錯資產。

官方參考：Gemini CLI Extension 發布。

9. 發布後驗收

  • 使用正式 URL／商店安裝
  • 使用新的對話或 CLI session
  • 確認三個 Skills 都能被發現
  • 測試一般小問題不誤觸發
  • 測試跨檔案任務會觸發
  • 確認計畫先於資源建議
  • 確認 ask 在建議後停留
  • 確認 auto 僅在有能力時套用
  • 確認語言跟隨使用者
  • 記錄平台、版本與實際結果

結構驗證、清單出現與實際行為是三種不同證據，發布後都要分別確認。

10. 後續版本更新

  1. 每次修改都開新分支

    從最新 main 建立 fix/*、feat/* 或 docs/* 分支，透過 PR 合併。

  2. 發布時再開 release 分支

    集中調整版本、Changelog、驗證紀錄與可重現產物。

  3. 建立新 tag

    已發布的 tag 不移動、不覆寫；修正版本使用新的 SemVer，例如 v0.4.3。

  4. 逐平台更新

    OpenAI 重新提交新版 ZIP；Claude 更新公開 repository／目錄版本；Gemini 推送新 tag，並以 --ref 驗證。

11. 常見錯誤

錯誤原因處理方式
Tag name can't be blankRelease 沒有指定有效 tag。輸入 vX.Y.Z 並選 Create new tag on publish，Target 指向 main。
Manifest 不在根目錄ZIP 或 repository 多包了一層資料夾。重新用專案建置腳本產生，不要手動壓縮外層目錄。
Claude 找不到 Skill只複製單一 Skill，遺漏 shared 或 sibling Skills。發布完整 Claude tree，並用 --strict 驗證。
Gemini 無法自動啟動舊 session 未重新載入 GEMINI.md，或 host 的 Skill tool 不可用。重新啟動 CLI，核對 extension list 與 skills list，再跑跨檔案測試。
Release checksum 不符建置後又手動修改 ZIP。刪除手動修改，重新執行 build 與 SHA256SUMS 驗證。
商店審核未通過發布者資料、公開網址或測試證據不完整。保留完整錯誤訊息，補齊欄位與可重現案例後再提交。
