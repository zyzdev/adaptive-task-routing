# Adaptive Task Routing：繁體中文參考

合併兩個 Router 結果時，在結構化證據中保留 Model Router 的任務能力需求、探測限制與證據範圍。除非使用者要求診斷，精簡結果不得顯示探測、備援／Registry 來源、新鮮度、介面／帳號適用性或無法讀取的目前值，只保留在地化的對話設定區塊、兩個 AI 設定區塊及可執行的下一步。未知目前設定不應抹去有用建議；已完成的暫時保留評估，與缺少子 Skill／目的地待定的未完成 Gate 不同。Context-only 不探測模型，也不重複子 Router 已做的查詢。

這是協調入口，負責依序載入兩個 Router 的指令並呈現結果；Context 與模型判斷仍由各自的 Skill 負責。宿主原生提醒可以要求模型先呼叫本 Skill，但實際是否完成仍要以子 Router 的載入與輸出為準。

## 何時使用

非瑣碎的多步任務已理解、初步計畫形成後，在大量執行前進入 Routing Gate。適用程式開發、除錯、架構、研究、分析及驗證。若回覆交付改善計畫並提出具體且有份量的下一階段，即使要等使用者批准才執行，也應先附上下一階段的 Routing 建議。

簡短說明、狀態詢問、小修改，以及僅詢問 Plugin 功能時，不必自動觸發。回答已完整且沒有實質下一階段時，不要為了 Routing 憑空增加工作。

## 順序與分工

1. 讀取共用政策及預設值。所有相對路徑都從目前 `SKILL.md` 所在目錄解析；Plugin 根目錄在主 Skill 檔往上三層，共用檔位於 `<plugin-root>/shared`，不是 `skills/shared`。分別解析 Context 與 Model 模式：`off`、`ask`、`auto`。沒有第三套協調入口模式或另一份固定路由策略。兩者均 `off` 時不評估、不探測能力、不輸出 Routing；只有一者關閉時，另一者照常運作。
2. 在 Context Gate 載入 `task-context-router`，由它決定 `CURRENT`／`HANDOFF`／`CLEAN`。Gemini 產物會把完整依賴附錄加在協調入口末端；附錄存在時直接使用其中的 Context Router 指令，不再嘗試啟動第二個 Skill。其他宿主可讀取 `../task-context-router/SKILL.md` 或使用宿主提供的 Skill 資源。後續只有模型需求改變時，可以沿用已確認的 Context。
3. 按模式確定實際工作 Context。`ask` 下建議 `CURRENT` 時直接繼續；建議改變時先暫停並詢問使用者。拒絕就沿用目前 Context；接受後，可呼叫且可驗證的操作由 AI 執行；`user_only` 的部分提供必要交接，讓使用者在目的地自然接續，不要求回覆特定口令。若目的地待確認且模型選項未知，明確顯示 Model Gate 延後，並顯示目前可取得的模型／強度或 `unknown`。
4. 載入 `research-model-router`，由它決定下一階段模型與強度。Gemini 的依賴附錄存在時，直接使用其中完整的 Model Router、宿主、Registry 與共同政策；其他宿主可讀取 `../research-model-router/SKILL.md` 或使用宿主提供的 Skill 資源。不能只期待宿主自行選到第二個 Skill。若相關檔案、附錄及宿主資源都無法取得，就顯示該元件無法載入，絕不依協調入口摘要或記憶自行補出結果。
5. 合併顯示精簡 Routing 訊息。先用獨立的【對話設定】區塊顯示使用者語言的白話建議，並明確回答是否切換視窗；`CURRENT`／`HANDOFF`／`CLEAN` 只留在結構化證據，不顯示在一般輸出，也不附在括號中。再列最低足夠模型／強度、建議模型／強度、升級價值及實際下一步。無法讀取的目前模型／強度不顯示。兩組符合已知目前設定時仍要顯示；延後或未載入不能當作已完成。
6. 繼續已授權工作，或在模式／任務需要決定時等待。只要求計畫，不等於授權實作。手動切換或環境改變後、執行之前要重檢。

協調流程已啟動時，兩個子 Router 不回頭呼叫協調入口，也不彼此呼叫。宿主若把一般任務直接分派給子 Router，子 Router 可依直接選取守門規則只轉交協調入口一次；協調入口傳入的委派標記會阻止循環。相同階段且環境、偏好未變時重用 Gate 結果，避免每則回覆都重複建議。

只辨識一次實際宿主介面，並把依據交給兩個子 Router。OpenAI 介面不能只因 Prompt 未寫 CLI 就預設成 Codex App；宿主資訊及使用者都未區分 CLI／App 時，Model Router 必須先依 OpenAI 指引使用有界的自動介面探測。

繁體中文的對話區塊使用這個格式，並換成本次實際理由：

```text
【對話設定】
* 建議：留在目前對話
* 是否切換視窗：否
目前對話保留了下一階段所需的需求與證據，因此直接繼續。
```

三種內部決策的繁體中文顯示分別是：「留在目前對話」、「切換到新對話並帶入精簡交接」及「開啟全新對話，不帶入目前脈絡」。使用其他語言時，所有標題、欄位與描述都改用該語言，不顯示英文 enum。

## 環境限制

每項宿主操作要分別解析。桌面、網頁或手機 App 可能允許 AI 建立 Context，但切換目前模型或強度仍是 `user_only`；CLI 也可能只有部分能力。只有操作可呼叫、已授權且驗證成功，才能說已切換。共用政策只在 Skill 載入後生效；平台封裝的啟動提醒可提高觸發一致性，但提醒本身不等於 Router 已完成。
