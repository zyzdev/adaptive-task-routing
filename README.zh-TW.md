# Adaptive Task Routing

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](docs/usage/README.zh-CN.md) · [日本語](docs/usage/README.ja.md) · [한국어](docs/usage/README.ko.md)

**讓 AI 的額度用在需要的地方，協助減少後續工作的遺漏與返工。**

Adaptive Task Routing 會在下一個重要工作階段開始前，建議是否開啟新對話，以及合適的模型與推理強度，協助你兼顧額度消耗與工作可靠度。

- **減少舊任務對新工作的干擾：** 判斷何時應開啟新對話，降低 AI 把上一個任務的假設或限制帶進新工作的機會，減少反覆糾正與返工；需要延續的資訊則整理後交接。
- **減少不必要的消耗：** 提供「最低足夠」與「建議」兩組模型及推理設定，說明升級是否值得，避免每個任務都使用最高設定。
- **降低遺漏與返工的風險：** 在複雜工作開始前，評估所需的模型能力與推理強度，降低設定不足造成的執行風險。
- **由你決定如何進行：** 可以先看建議再決定，也能選擇在平台支援時自動套用設定。

換了主題不代表一定要開新對話；重點是減少無關歷史的干擾，同時保留下一個任務需要的資訊。實際節省與可靠度改善取決於任務及採用的設定。

**只在任務階段邊界路由，不因每個 Prompt 重選模型。** 保留有價值的脈絡；目前模型適任，而且剩餘階段的收益不足以抵銷設定、快取、延遲或返工成本時，優先維持設定。建議較強模型不代表現在值得切換。`auto` 也只有在切換值得、平台支援且操作可驗證時才變更設定。目標是兼顧整體任務成本與可靠完成，實際節省需要證據。

模型選得對，放在不適合的對話脈絡中，仍然不是合適的配置。

## 運作方式

1. AI 先提出可執行計畫，或完成你要求的分析與檢查結果。
2. Plugin 評估下一階段：先建議保留或開啟新對話，再提供最低足夠與建議的模型、推理強度，以及升級價值。
3. 預設的 `ask` 模式會等待你的決定；`auto` 模式在平台支援且能驗證時套用設定，無法切換時會說明並沿用目前設定，繼續已授權的工作。

一般問答與微小操作會略過路由，避免增加不必要的判斷與等待。

## 第一次使用

安裝並啟用後，開啟新對話，輸入具有一定規模的任務，例如：

> 我想檢查這個 Plugin 的發布流程、跨平台一致性與測試缺口。請先提出執行計畫。

若未出現建議，也可以明確要求：「開始下一階段前，請使用 adaptive-task-routing Skill。」

## 你會看到什麼

以下是上述任務的回覆範例。實際計畫、模型與推理強度會依任務及平台調整。

### 回覆範例

#### 1. AI 的任務計畫

```text
1. 核對發布腳本與各平台 Manifest。
2. 檢查 CI、版本一致性與測試缺口。
3. 整理風險並提出修改順序。
```

#### 2. Adaptive Task Routing 的資源建議

```text
---

### Adaptive Task Routing｜任務資源建議

以下建議是根據上述計畫的下一階段，評估適合的對話環境、模型與推理設定。

【對話設定】

- 建議：留在目前對話
- 是否切換視窗：否

目前對話已包含專案位置與檢查目標，直接延續最合適。

【最低足夠 AI 設定】

- Model：GPT-5.6 Sol
- Reasoning：high

足以檢查發布腳本、平台差異與現有測試覆蓋。

【建議 AI 設定】

- Model：GPT-6 Astra
- Reasoning：high
- 升級價值：中。較適合交叉追蹤發布流程、平台條件分支與隱性失敗路徑。

切換評估：效益尚未確立，暫不自動調整設定。

目前保留設定；我先停在這裡，等你決定下一步。
```

這是無法自動切換設定時的 `ask` 模式範例。Claude 與 Gemini 會使用各自平台的模型選項；操作提示也會依介面調整。

## 在對話中切換模式

直接告訴 AI 即可：

- 「這個對話的 Adaptive Task Routing 改用 auto。」
- 「模型路由改成 ask。」
- 「這次關閉對話路由。」
- 「目前兩個路由模式是什麼？」

| 模式 | 行為 |
| --- | --- |
| `ask`（預設） | 顯示建議後停下，等待你的決定。 |
| `auto` | 套用已允許、平台支援且能驗證的變更，繼續已授權的工作；無法代為完成的操作會說明實際處置。 |
| `off` | 關閉指定的路由評估。 |

對話路由與模型路由可以分別設定。未指定路由的模式切換會同時套用兩者。你可以自然回覆、調整建議或要求沿用目前設定，不必使用固定口令。

## 建議根據什麼？

- **對話環境：** 評估下一個任務需要沿用哪些資訊，以及舊任務的假設或限制是否可能干擾新工作，再建議保留對話、整理資訊後交接，或從新對話開始。
- **模型與推理強度：** 考量任務難度、模糊度、錯誤成本與驗證需求，提供最低足夠及建議設定，並說明提高設定是否值得。
- **模型資訊來源：** 優先使用目前環境可取得的資訊；無法取得時，依平台使用套件內有效的參考資料。參考資料不代表你的帳號一定能選用該模型。

完整判斷原則與平台限制可查閱[設計與架構](docs/architecture.zh-TW.md)。
