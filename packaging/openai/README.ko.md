# ChatGPT 및 Codex용 Adaptive Task Routing

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**필요한 작업에 AI 사용량을 쓰고, 누락과 재작업을 줄이도록 돕습니다.**

Adaptive Task Routing은 다음 주요 작업 단계를 시작하기 전에 새 대화가 필요한지, 어떤 모델과 추론 강도가 적합한지 추천하여 사용량과 작업 신뢰성 사이의 균형을 잡도록 돕습니다.

- **이전 작업이 새 작업에 미치는 간섭 줄이기:** 새 대화를 시작할 시점을 판단하여 AI가 이전 작업의 가정이나 제약을 새 작업에 적용할 가능성을 낮춥니다. 반복적인 수정 요청과 재작업을 줄이고, 이어서 사용할 정보는 필요에 따라 요약해 전달합니다.
- **불필요한 사용량 줄이기:** ‘최소 충분’ 설정과 ‘권장’ 설정을 제시하고 상향 조정의 가치를 설명하여 모든 작업에 최고 설정을 쓰지 않도록 돕습니다.
- **누락과 재작업의 위험 낮추기:** 복잡한 작업을 시작하기 전에 필요한 모델 능력과 추론 강도를 평가하여 작업에 부족한 설정으로 인한 실패 위험을 낮춥니다.
- **최종 결정은 사용자에게:** 추천을 보고 결정하거나, 플랫폼이 지원하는 경우 자동 적용을 선택할 수 있습니다.

주제가 바뀌었다고 반드시 새 대화가 필요한 것은 아닙니다. 불필요한 대화 기록의 영향을 줄이면서 다음 작업에 필요한 정보를 유지하는 것이 목적입니다. 실제 사용량 절감과 신뢰성 개선은 작업과 채택한 설정에 따라 달라집니다.

**프롬프트마다 모델을 다시 고르지 않고, 작업 단계가 바뀔 때 판단합니다.** 유용한 맥락을 유지하고 현재 모델이 적합하다면, 남은 단계의 이득이 설정·캐시·지연·재작업 비용을 넘지 않는 한 설정을 유지합니다. 더 강한 모델을 추천한다고 지금 전환할 가치가 있다는 뜻은 아닙니다. `auto`에서도 전환할 가치가 있고 지원되는 작업의 결과를 검증할 수 있을 때만 설정을 변경합니다. 목표는 전체 작업 비용과 신뢰할 수 있는 완료의 균형이며, 실제 절감에는 근거가 필요합니다.

적합한 모델도 부적절한 대화 맥락에서는 적합한 구성이 아닙니다.

## 작동 방식

1. AI가 실행 가능한 계획을 제시하거나 요청한 분석 및 점검 결과를 정리합니다.
2. 다음 단계를 평가하여 먼저 현재 대화를 유지할지 새로 시작할지 추천한 뒤, 최소 충분 및 권장 모델과 추론 설정, 상향 조정의 가치를 제시합니다.
3. 기본 `ask` 모드는 사용자의 결정을 기다립니다. `auto`는 플랫폼이 지원하고 결과를 검증할 수 있는 변경을 적용합니다. 전환할 수 없으면 이를 알리고 현재 설정을 유지한 채 이미 승인된 작업을 계속합니다.

짧은 질문과 작은 작업은 라우팅을 생략하여 불필요한 판단과 대기 시간을 줄입니다.

## 설치

공개 Plugin은 OpenAI Plugins portal에서 관리됩니다. 공개 전에는 [최신 릴리스](https://github.com/zyzdev/adaptive-task-routing/releases/tag/v0.4.2)에서 `adaptive-task-routing-openai-0.4.2.zip`을 다운로드하고 압축을 푼 뒤, 해당 디렉터리를 로컬 Plugin 소스 또는 Marketplace로 등록하세요.

Codex CLI에서는 설정된 Marketplace에서 설치할 수 있습니다. 공개된 후에는 ChatGPT와 Codex App의 Plugins Directory에서 선택할 수 있습니다.

## 처음 사용하기

새 대화를 시작하고 규모가 있는 작업을 입력합니다. 예:

> 이 프로젝트의 릴리스 흐름을 점검하고 주요 위험에 대한 구현 계획을 제안해 주세요.

이름이 있는 Skill을 지원하는 화면에서는 `$adaptive-task-routing`으로 명시적으로 활성화할 수 있습니다.

## 표시되는 내용

아래는 ‘Plugin의 릴리스 과정, 플랫폼 간 일관성 및 테스트 누락을 점검해 주세요’라는 요청의 예시입니다. 실제 계획과 권장 사항은 작업 및 플랫폼에 따라 달라집니다.

### 응답 예시

#### 1. AI 작업 계획

```text
1. 릴리스 스크립트와 Manifest를 확인한다.
2. CI와 테스트 누락을 확인한다.
3. 위험을 정리하고 수정 순서를 제안한다.
```

#### 2. Adaptive Task Routing 리소스 권장 사항

```text
---

### Adaptive Task Routing｜작업 리소스 추천

【대화 설정】
* 추천: 현재 대화 유지
* 창 전환: 아니요

【최소 충분 AI 설정】
* Model: GPT-5.6 Sol
* Reasoning: high

【권장 AI 설정】
* Model: GPT-6 Astra
* Reasoning: high
* 업그레이드 가치: 중간. 놓치기 쉬운 파일 간 의존성을 추적하는 데 유리합니다.

전환 평가: 이득이 아직 확인되지 않아 자동 변경을 보류합니다.

현재 설정을 유지하고 다음 진행 방식에 대한 사용자의 결정을 기다립니다.
```

모델 이름과 강도는 예시입니다. 실제 추천은 현재 OpenAI 환경에서 확인된 선택지만 사용합니다. `ask`는 여기서 멈추며 `auto`는 이미 승인된 작업을 계속할 수 있습니다.

## 대화에서 모드 변경

- “이 대화에서는 Adaptive Task Routing을 auto로 설정해 주세요.”
- “모델 라우팅을 ask로 설정해 주세요.”
- “이 작업에서는 대화 라우팅을 꺼 주세요.”
- “현재 라우팅 모드는 무엇인가요?”

Router를 지정하지 않은 변경은 두 라우터에 모두 적용됩니다. 기본값은 `ask`입니다. `auto`는 현재 OpenAI 화면에서 실행하고 검증할 수 있는 변경만 적용하며, `off`는 지정한 Router를 건너뜁니다.

## 추천의 판단 기준

- **대화 환경:** 다음 작업에 필요한 정보와 이전 작업의 가정이나 제약이 새 작업에 간섭할 가능성을 평가합니다. 이를 바탕으로 현재 대화 유지, 필요한 정보 요약 후 전달, 새 대화 시작 중 적합한 방법을 추천합니다.
- **모델과 추론 강도:** 작업 난이도, 모호함, 오류 비용과 검증 필요성을 고려하여 최소 충분 설정과 권장 설정을 제시하고, 상향 조정의 가치를 설명합니다.
- **모델 정보 출처:** 현재 환경에서 얻을 수 있는 정보를 우선 사용합니다. 얻을 수 없다면 플랫폼에 맞는 유효한 내장 참고 자료를 사용합니다. 참고 자료에 있는 모델이라도 사용자의 계정에서 선택할 수 있다는 뜻은 아닙니다.

자세한 판단 원칙과 플랫폼 제약은 [설계 및 아키텍처(영어)](../../docs/architecture.md)를 참고하세요.
