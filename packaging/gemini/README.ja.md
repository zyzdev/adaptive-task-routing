# Adaptive Task Routing for Gemini CLI

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**次に何をするか、そして変更が不要なときを明確に。**

Adaptive Task Routing は作業段階の境界で会話・モデル・推論設定を評価し、まず今の推奨アクション、次に理由を示します。タスクに適したモデルが、作業途中で切り替える価値のあるモデルとは限りません。

タスクの要件、現在の設定の適性、残りの作業量、会話の連続性、切り替えコストを考慮します。適切な設定の維持も有効な結果です。情報不足なら「暫定的に維持」とし、適性を確認済みとは表現しません。実際の節約や信頼性の向上には検証が必要です。

> このページは未リリースの UX 更新を説明しています。公開済み v0.4.2 は以前の動作です。試す場合は開発ブランチのビルドを使用してください。

## 仕組み

1. AI は依頼された分析結果、または実行可能な計画を先に提示します。
2. ルーティング欄は維持、暫定維持、新しい会話、設定変更、必要な判断の順に該当アクションを示します。会話ルーティングが有効ならウィンドウ切り替えの要否も明示します。
3. 既定の `ask` は変更前や重要な支障がある場合に確認します。維持や進行を妨げない不確実性では承認済みの作業を中断しません。計画の依頼は実装の承認ではありません。

短い質問や変更のない段階では再評価しません。会話とモデルは別々に判断し、引き継ぎとモデル変更が同時に必要な場合もあります。

## インストール

```bash
gemini extensions install https://github.com/zyzdev/adaptive-task-routing-gemini --ref v0.4.2
```

インストール後に Gemini CLI を再起動し、`gemini extensions list` で確認してください。

## 最初の使い方

有効化後に新しい会話で入力します：

> このプロジェクトを調べて改善計画を提案してください。まだファイルは変更しないでください。

必要なら adaptive-task-routing Skill の利用を明示します。計画の後に提案が表示されますが、実装は開始しません。

## 表示される内容

次の例は別々の状況を示し、分析や計画の後に表示されます。維持の例では確認作業が承認済みと仮定します。計画のみの依頼なら計画を渡して終了します。モデルとネイティブ推論設定は例示です。「現在の AI」には実際の観測が必要です。

**切り替える価値が小さい場合**

```text
---

### Adaptive Task Routing｜タスクリソースの提案

✓ 現在の設定を維持
現在の設定で十分であり、残りの作業量では切り替えの効果が限定的です。

会話：現在の会話を続ける。ウィンドウを切り替える：いいえ。
現在の AI：Flash / モデル既定値。

操作は不要です。承認済みの確認作業を続けます。
```

**変更する価値がある場合**

```text
---

### Adaptive Task Routing｜タスクリソースの提案

AI 設定を変更
次の段階の検証要件は、観測済みの現在の設定の能力を上回ります。

会話：現在の会話を続ける。ウィンドウを切り替える：いいえ。
タスクに適した設定：Pro / モデル既定値。

この設定を採用しますか。それとも次の段階の計画を調整しますか。
```

操作方法は環境に依存します。`auto` でも変更の完了を検証してから報告します。情報不足なら暫定維持と理由を示し、適性を断定しません。重大な支障がある場合は具体的に質問します。

計画のみの依頼なら、計画の完了と実装未着手を伝えます。引き継ぎが必要ならウィンドウ切り替えの確認と、必要な事実・制約の要約を提示します。

## モードと表示の詳しさ

| モード | 動作 |
| --- | --- |
| `ask`（既定） | 変更前や重大な支障がある場合に確認。維持や支障のない defer では承認済み作業を続行。 |
| `auto` | 妥当で承認済み、操作可能かつ検証可能な変更のみ適用。代替動作を説明し、重大な支障を無視しない。 |
| `off` | 指定 Router とその出力を省略。 |

Context と Model は独立しています。「今回は会話ルーティングを off」「モデルルーティングは ask」「この会話では両方 auto」と指定できます。モード変更だけでは作業を承認しません。

既定は簡潔な表示です。「詳しく説明して」と依頼すると、**最低限必要な設定、タスクに適した設定、引き上げる価値**を表示します。適した設定と今のアクションは別の判断です。詳細表示は既存の評価を再利用し、切り替えスコアは診断用に留めます。compact／detailed は追加モードではありません。

## 提案の判断基準

- **会話環境：** 次のタスクに必要な情報と、以前の前提や制約が新しい作業に影響する可能性を評価します。そのうえで、現在の会話を続けるか、必要な情報をまとめて引き継ぐか、新しく始めるかを提案します。
- **モデルと推論強度：** 難易度、曖昧さ、誤りの影響、検証の必要性を考慮して、最低限十分な設定とタスクに適した設定を示し、設定を引き上げる価値を説明します。
- **モデル情報の参照元：** 現在の環境から取得できる情報を優先します。取得できない場合は、プラットフォームに適した有効な同梱資料を参照します。参照資料に載っていても、自分のアカウントで選択できるとは限りません。

詳しい判断原則とプラットフォームの制限は[設計とアーキテクチャ（英語）](../../docs/architecture.md)を参照してください。
