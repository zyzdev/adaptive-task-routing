# Adaptive Task Routing for Gemini CLI

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**必要な作業に AI の利用枠を使い、見落としや手戻りを減らすために。**

Adaptive Task Routing は、次の重要な作業段階に入る前に、新しい会話を始めるべきか、どのモデルと推論強度が適しているかを提案し、利用量と作業の信頼性のバランスを取る手助けをします。

- **以前のタスクによる干渉を減らす：**新しい会話を始めるタイミングを判断し、AI が以前の前提や制約を新しい作業に持ち込む可能性を下げます。繰り返しの訂正や手戻りを減らし、引き継ぐべき情報は必要に応じて要約します。
- **不要な利用量を抑える：**「最低限十分」と「推奨」のモデル・推論設定を示し、引き上げる価値があるかを説明します。すべてのタスクで最高設定を使う必要はありません。
- **見落としや手戻りのリスクを下げる：**複雑な作業の開始前に必要なモデル能力と推論強度を評価し、能力不足の設定による失敗を減らす手助けをします。
- **最終判断はユーザーに：**提案を見てから決めることも、プラットフォームが対応していれば自動適用を選ぶこともできます。

話題が変わっただけで新しい会話が必要になるわけではありません。不要な履歴の影響を減らしつつ、次のタスクに必要な情報を残すことが目的です。実際の節約や信頼性の改善は、タスクと採用した設定に左右されます。

## 仕組み

1. AI が実行可能な計画を提示するか、依頼された分析や確認結果をまとめます。
2. 次の段階について、まず会話を続けるか新しく始めるかを提案し、続いて最低限十分な設定、推奨設定、設定を引き上げる価値を示します。
3. 既定の `ask` はユーザーの判断を待ちます。`auto` は対応していて結果を検証できる変更を適用します。切り替えられない場合はその旨を伝え、現在の設定で承認済みの作業を続けます。

短い質問や小さな操作ではルーティングを省略し、不要な判断や待ち時間を増やしません。

## インストール

```bash
gemini extensions install https://github.com/zyzdev/adaptive-task-routing-gemini --ref v0.4.2
```

インストール後に Gemini CLI を再起動し、`gemini extensions list` で確認してください。

## 最初の使い方

新しいセッションを開始し、ある程度大きなタスクを入力します。例：

> このプロジェクトのリリース手順を監査し、主なリスクの実装計画を作成してください。

明示的に起動する場合は、`adaptive-task-routing` Skill を使用するよう Gemini に依頼します。

## 会話でモードを変更する

- 「この会話では Adaptive Task Routing を auto にしてください」
- 「モデルルーティングを ask にしてください」
- 「今回だけ会話ルーティングを off にしてください」
- 「現在の二つのルーティングモードを教えてください」

Router を指定しない変更は両方に適用されます。既定は `ask`、`auto` は Gemini が実行して検証できる変更だけを適用し、`off` は指定した Router を省略します。

## 表示される内容

以下は「プラグインのリリース工程、プラットフォーム間の整合性、テスト不足を確認する」という依頼の例です。実際の計画と提案は、タスクやプラットフォームに応じて変わります。

### 応答例

#### 1. AI のタスク計画

```text
1. リリーススクリプトと Manifest を確認する。
2. CI とテストの不足を確認する。
3. リスクを整理し、修正の順序を提案する。
```

#### 2. Adaptive Task Routing のリソース提案

```text
---

### Adaptive Task Routing｜タスクリソースの提案

【会話設定】
* 提案：現在の会話を続ける
* ウィンドウを切り替える：いいえ

【最低限十分な AI 設定】
* Model：Flash
* Reasoning：モデル既定値

【推奨 AI 設定】
* Model：Pro
* Reasoning：モデル既定値
* アップグレード価値：中。見落としやすいファイル間の依存関係を追跡しやすくなります。

現在の環境ではモデルを自動変更できません。推奨モデルを使う場合は /model で選択してください。変更するか現在の設定を使うか決まるまで、ここで待機します。
```

モデル別名は例であり、現在の Gemini アカウントに応じて解決されます。セッションに明示的な思考設定がある場合だけその値を表示し、それ以外はモデル既定値を使用します。`ask` はここで停止し、`auto` は承認済みの作業を続けられます。

## アンインストール

```bash
gemini extensions uninstall adaptive-task-routing
```

削除後に Gemini CLI を再起動してください。
